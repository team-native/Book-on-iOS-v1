# BookOn iOS

SwiftUI iOS app for school library search, book details, favorites, loans, and notifications.

## Requirements

- macOS with Xcode and the iOS Simulator
- [mise](https://mise.jdx.dev/) for the pinned Tuist and SwiftLint versions

## Setup

```sh
mise install
tuist install
tuist generate --no-open
swiftlint lint --strict --baseline .swiftlint-baseline.json
```

Open `Book-on-iOS-V1.xcworkspace` and run the `Book-on-iOS-V1` scheme. The workspace is generated by Tuist and should not be committed.

The app uses `https://bookon.team-native.kr` as its default API base URL. Local or CI overrides can be supplied through `BOOK_ON_API_BASE_URL`; otherwise, the `API_BASE_URL` Info.plist value is used.

Firebase push support is optional for local development. If `Projects/App/Resources/GoogleService-Info.plist` is missing, the app skips Firebase initialization. Provide that environment-specific file securely when building with Firebase; it is ignored by Git.

## Modules

- `Projects/App`: app lifecycle, authentication routing, and push notifications
- `Projects/Feature`: SwiftUI screens and view models
- `Projects/Service`: API clients, models, authentication, and service calls

## Build and tests

Pull requests targeting `dev` run SwiftLint, an unsigned simulator build, Service and Feature unit tests, and app UI tests. The unit-test schemes can also be run locally:

```sh
xcodebuild test \
  -workspace Book-on-iOS-V1.xcworkspace \
  -scheme Service \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  CODE_SIGNING_ALLOWED=NO
```

A passing simulator run does not verify APNs delivery; push notifications require a signed physical-device check.

## Signing files

Signing keys, certificates, and provisioning profiles are local credentials. Keep them outside the repository and provide CI signing assets through GitHub Actions secrets.
